SPOTTR — comparație React Native / Next.js, 27 octombrie 2026

Scop și metodă
Comparate implementările locale din apps/spottr-native și apps/pulse-app:
rute, ecrane, acțiuni, cereri API și logica reutilizată. Comparația include
modificările necomise existente în workspace. React Native Web este versiunea
web a apps/spottr-native; nu este aplicația Next.js din apps/pulse-app.

Acesta este un audit de cod și de paritate, nu o nouă certificare end-to-end.
Nu au fost rulate acum plăți reale, verificări pe iPhone sau operații AWS.
Nu au fost schimbate implementările aplicațiilor în timpul acestui audit.
Testele locale precedente sunt documentate separat în:
  docs/qa/features-audit-2026-10-26.txt
  docs/qa/purchase-scanner-2026-10-26.txt
Ele verifică scenariile implementate; trecerea lor nu dovedește paritate 1:1.

Rezultat
Modulele principale există în ambele aplicații. Next.js nu include însă toate
îmbunătățirile adăugate ulterior în React Native. Mai jos sunt diferențe
concrete identificate în implementarea locală, nu o listă de pagini dedusă
doar din numele fișierelor.

Diferențe de adus în Next.js

01. Scanner: tabul Management este afișat și conturilor fără administrare.
    Next: cele două taburi sunt necondiționate; conținutul Management este
    condiționat de rol/canManage. Rezultatul poate fi un tab fără conținut.
    RN: taburile apar doar când event.canManage este true; schimbarea pe un
    eveniment fără drepturi selectează automat Scan.
    Prioritate: ridicată — problemă de interfață pentru personalul desemnat;
    nu rezultă de aici că backendul permite operații neautorizate.
    Next: apps/pulse-app/src/app/dashboard/ticket-validation/page.tsx:830
    RN: apps/spottr-native/src/scanner/ScannerScreen.tsx:171 și :714

    RN: cere /scans?scope=all|mine, afișează scannedBy și încarcă paginile
    următoare. Are ecran propriu cu navigație înapoi prin stackul nativ.

Diferențe în sens invers și reguli care merită unificate
- Recomandările search din Next prioritizează favoritele, apoi goingCount,
  apoi data. RN ordonează recomandările doar după startTime. Dacă regula din
  Next este cea dorită, ea trebuie reutilizată și în RN.
  Next: apps/pulse-app/src/components/SearchPopover.tsx:125
  RN: apps/spottr-native/src/screens/SearchScreen.tsx:55
- Nu am identificat în modulele parcurse un dashboard, admin, garderobă sau
  alt modul principal disponibil numai în Next și complet absent din RN.
  Aceasta nu este o garanție că toate microinteracțiunile sunt identice.

Module găsite în ambele implementări
- Autentificare, recuperare cont, profil public, preferințe, ștergere cont.
- Descoperire evenimente, hartă, filtre, pagină și sheet de eveniment.
- Cumpărare, rezervare, cod promoțional, date de facturare, bilete și PDF,
  listarea comenzilor și facturilor. Formularele Stripe diferă după platformă.
- Scanner online/offline, pachete și sincronizare. Next folosește deja
  scanare continuă și protecție împotriva citirilor repetate ale aceluiași QR;
  acestea nu trebuie raportate ca funcții absente.
- Garderobă: QR de cont, numere, personal, predare/retur, aprobări și Neridicate.
  RN reutilizează WardrobeStore din Next:
  apps/spottr-native/src/wardrobe/useWardrobe.ts:8
- Dashboard: evenimente, creare/editare, statistici, bilete/invitații,
  coduri promoționale, actualizări, anulare, promovare, finanțe, companie,
  facturare, Stripe Connect și acord organizator.
- Admin: verificare organizatori, anulări/refunduri, atenționări facturare,
  erori aplicație și comisioane standard/negociate.
- Social: prieteni, cereri, profil QR, urmărire organizator, grup/ajutor.
- Calculul comisionului este reutilizat de RN din
  apps/pulse-app/src/features/events/serviceFee.ts (5% + 1,50 lei/bilet,
  cu posibilitatea configurației negociate), prin checkout/data.ts.

Diferențe de platformă, nu module lipsă
- Liquid Glass și SF Symbols adăugate acum sunt în implementările .ios.tsx
  ale navbarului RN. Next folosește CSS și iconițe Lucide. Acestea nu se
  propagă automat între aplicații și nu devin componente native în browser.
- Swipe-back iOS, tastatura nativă, luminozitatea biletului și vibrațiile
  folosesc API-uri native. Interfața web are nevoie de comportament web.
- RN are mod poartă cu comenzi de sunet/vibrație și menținerea ecranului
  aprins (GateToolbar/useGateExperience). Next nu oferă aceeași bară.
- Push-urile native au integrare proprie și depind de configurarea buildului;
  existența codului nu dovedește activarea lor pe un Personal Team gratuit.

Ordine recomandată de aliniere
1. Permisiunile vizuale scanner, istoric all/mine și fluxul de confirmare.
2. Navbar pe subpagini, profil/bilete și notificările mark-all.
3. Search, story, refresh și bannerul din Home.
4. Decizia separată pentru wallet offline în web/PWA, apoi verificare UI
   în ambele aplicații cu aceleași date și aceleași roluri.

Aspecte de curățat fără a le confunda cu buguri vizibile
Next users/me/page.tsx mai conține orderHistory demonstrativ. Cele două
randări ale sale sunt ascunse prin clasa hidden; auditul nu susține că aceste
comenzi fictive sunt afișate utilizatorilor sau că ar fi comenzi reale.
